## 1. 서론

최근 생성형 AI를 활용하여 자연어로 코드를 작성하거나 수정하는 바이브코딩 방식이 주목받고 있다. 바이브코딩은 개발자가 원하는 기능을 자연어로 설명하면 AI가 코드 초안, 오류 수정 방법, 문서 구조 등을 제안해 주는 방식이다.

본 보고서는 바이브코딩을 단순히 즉흥적인 코드 생성 방식으로 사용하는 것이 아니라, 요구사항 분석, 설계, 구현, 테스트, 품질 관리에 이르는 소프트웨어공학 프로세스와 결합했을 때 어떤 효과가 있는지 분석하는 것을 목적으로 한다.

이를 위해 본 프로젝트에서는 `CapBox`라는 웹 기반 스크린샷 텍스트 아카이빙 서비스를 개발하였다. CapBox는 사용자가 스크린샷 이미지를 업로드하면 OCR을 통해 이미지 속 텍스트를 추출하고, 사용자가 이를 수정한 뒤 저장하며, 이후 키워드 검색과 유사도 검색으로 다시 찾을 수 있도록 돕는 서비스이다.

본 프로젝트는 2026년 5월 17일부터 2026년 6월 7일까지 진행하였으며, 개발 과정은 GitHub 문서와 커밋 기록으로 남겼다.

## 2. 프로젝트 개요

### 2.1 프로젝트명

CapBox

### 2.2 프로젝트 주제

스크린샷 이미지에서 텍스트를 추출하고, 저장된 텍스트를 나중에 검색어로 다시 찾을 수 있도록 돕는 웹 기반 아카이빙 서비스

### 2.3 개발 목적

일상적으로 사용자는 쇼핑 정보, 과제 안내, 일정, 게시글, 메모 등을 스크린샷으로 저장한다. 하지만 시간이 지나면 어떤 스크린샷에 어떤 정보가 들어 있었는지 다시 찾기 어렵다.

CapBox는 이러한 문제를 해결하기 위해 스크린샷 속 텍스트를 추출하고 저장하여, 사용자가 나중에 검색어로 필요한 정보를 다시 찾을 수 있도록 한다.

### 2.4 주요 기능

- 스크린샷 이미지 업로드
- 이미지 미리보기
- OCR을 통한 텍스트 추출
- OCR 결과 확인 및 수정
- SQLite 기반 텍스트 저장
- 저장된 아카이브 목록 조회
- 키워드 검색
- 유사도 검색
- 하이브리드 검색
- 빈 입력 및 검색 결과 없음 예외 처리

### 2.5 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 언어 | Python |
| 웹 프레임워크 | Streamlit |
| OCR | EasyOCR |
| 데이터베이스 | SQLite |
| 이미지 처리 | Pillow |
| 유사도 검색 | sentence-transformers, cosine similarity |
| 버전 관리 | Git, GitHub |

## 4. 요구사항 분석

초기 아이디어는 사용자가 모바일에서 스크린샷을 찍고 앱으로 공유하면, 이미지 속 텍스트를 자동으로 추출하여 저장하는 서비스였다.

그러나 과제 기간과 구현 난도를 고려했을 때 모바일 앱 공유 기능, 갤러리 자동 접근, 로그인, 클라우드 저장까지 모두 구현하는 것은 범위가 크다고 판단하였다. 따라서 요구사항 분석 단계에서 핵심 기능 중심의 MVP로 범위를 축소하였다.

### 4.1 MVP 범위

이번 프로젝트의 MVP는 다음 기능에 집중하였다.

- 사용자가 웹에서 이미지를 업로드한다.
- OCR로 이미지 속 텍스트를 추출한다.
- 사용자가 OCR 결과를 확인하고 수정한다.
- 수정된 텍스트를 SQLite에 저장한다.
- 저장된 내용을 목록으로 확인한다.
- 키워드 검색과 유사도 검색으로 다시 찾는다.

### 4.2 제외한 기능

다음 기능은 이번 MVP 범위에서 제외하였다.

- 모바일 앱 공유 기능
- 갤러리 자동 접근
- 로그인 및 회원가입
- 클라우드 저장
- 이미지 원본 저장
- 태그 및 카테고리 기능
- 저장 항목 수정 및 삭제 기능

### 4.3 요구사항 분석의 의의

요구사항 분석을 통해 프로젝트 범위를 현실적으로 조정할 수 있었다. 바이브코딩을 활용하면 다양한 기능을 빠르게 제안받을 수 있지만, 모든 기능을 구현하는 것은 오히려 프로젝트를 복잡하게 만들 수 있다.

따라서 본 프로젝트에서는 AI의 도움을 받되, 과제 기간과 핵심 목적을 기준으로 구현 범위를 조정하였다.

## 5. 설계

설계 단계에서는 화면 흐름, 데이터 구조, 모듈 구조를 정리하였다.

### 5.1 사용자 흐름

CapBox의 기본 사용자 흐름은 다음과 같다.

```text
이미지 업로드
→ 이미지 미리보기
→ OCR 실행
→ OCR 결과 확인 및 수정
→ 제목과 함께 저장
→ 저장 목록 조회
→ 키워드/유사도/하이브리드 검색
```

### 5.2 데이터베이스 설계

SQLite의 `archive` 테이블을 사용하여 저장된 텍스트를 관리하였다.

| 컬럼명 | 타입 | 설명 |
|---|---|---|
| id | INTEGER | 기본키 |
| title | TEXT | 저장 항목 제목 |
| content | TEXT | OCR 추출 및 수정된 본문 |
| created_at | TEXT | 저장 시각 |

### 5.3 모듈 구조

| 파일 | 역할 |
|---|---|
| app.py | Streamlit 화면 및 전체 사용자 흐름 제어 |
| ocr_utils.py | OCR 텍스트 추출 기능 |
| db.py | SQLite 저장 및 조회 기능 |
| search_utils.py | 키워드 검색, 유사도 검색, 하이브리드 검색 기능 |

### 5.4 설계의 의의

기능별로 파일을 분리하여 유지보수성을 높였다. 모든 코드를 `app.py`에 작성하지 않고 OCR, DB, 검색 기능을 각각 모듈화했기 때문에 이후 검색 기능 개선이나 저장 기능 수정이 쉬워졌다.

## 6. 구현

### 6.1 Streamlit 화면 구현

Streamlit을 사용하여 웹 기반 UI를 구현하였다. 사용자는 별도의 복잡한 설치 없이 브라우저에서 이미지를 업로드하고, OCR 결과를 확인하며, 저장 및 검색 기능을 사용할 수 있다.

### 6.2 OCR 기능 구현

EasyOCR을 사용하여 이미지 속 한글과 영어 텍스트를 추출하였다. OCR 모델 로딩 시간이 발생할 수 있기 때문에 Streamlit의 cache 기능을 사용하여 반복 로딩을 줄였다.

OCR 결과는 바로 저장하지 않고, 사용자가 직접 확인하고 수정할 수 있도록 text area에 표시하였다.

### 6.3 SQLite 저장 기능 구현

OCR 결과와 제목을 SQLite 데이터베이스에 저장하였다. 제목이 입력되지 않은 경우 본문 앞부분을 자동으로 제목으로 사용하도록 하였다. 본문이 비어 있는 경우에는 저장하지 않고 경고 메시지를 표시하였다.

### 6.4 저장 목록 조회 기능 구현

저장된 아카이브를 최신순으로 조회하여 화면에 표시하였다. 각 항목은 expander 형태로 구성하여 제목과 저장 시각을 먼저 보여주고, 클릭하면 본문을 확인할 수 있도록 하였다.

### 6.5 키워드 검색 구현

키워드 검색은 사용자가 입력한 단어가 저장된 제목 또는 본문에 포함되어 있는지를 기준으로 결과를 반환한다. 정확한 상품명, 브랜드명, 과제 키워드 등을 찾을 때 유용하다.

### 6.6 유사도 검색 구현

유사도 검색은 sentence-transformers 모델을 사용하여 검색어와 저장된 텍스트를 임베딩 벡터로 변환하고, cosine similarity를 계산하여 의미적으로 유사한 결과를 반환한다.

### 6.7 하이브리드 검색 구현

유사도 검색 테스트 결과 짧은 상품명이나 브랜드명에서 부정확한 결과가 나올 수 있음을 확인하였다. 이를 보완하기 위해 키워드 검색을 먼저 수행하고, 결과가 없을 때 유사도 검색을 수행하는 하이브리드 검색을 적용하였다.

## 7. 테스트

### 7.1 테스트 계획

테스트는 다음 기능을 대상으로 진행하였다.

- 이미지 업로드
- OCR 텍스트 추출
- OCR 결과 수정
- SQLite 저장
- 저장 목록 조회
- 키워드 검색
- 유사도 검색
- 하이브리드 검색
- 예외 상황 처리

### 7.2 테스트 결과 요약

| 구분 | 결과 |
|---|---|
| 이미지 업로드 | 성공 |
| OCR 텍스트 추출 | 부분 성공 |
| OCR 결과 수정 | 성공 |
| SQLite 저장 | 성공 |
| 저장 목록 조회 | 성공 |
| 키워드 검색 | 성공 |
| 유사도 검색 | 부분 성공 |
| 하이브리드 검색 | 성공 |
| 예외 처리 | 성공 |

OCR과 유사도 검색은 입력 이미지와 검색어 형태에 따라 결과가 달라졌기 때문에 부분 성공으로 기록하였다.

### 7.3 OCR 테스트 결과

테스트 과정에서 다음과 같은 OCR 오인식 사례를 확인하였다.

| 원본 | OCR 결과 |
|---|---|
| 젤 | 절 |
| 살몬 | 살문 |
| 댓글 | 대글 |

이를 통해 OCR 결과를 그대로 저장하는 것은 위험할 수 있으며, 사용자가 저장 전에 직접 수정할 수 있도록 한 설계가 필요하다는 점을 확인하였다.

### 7.4 유사도 검색 테스트 결과

유사도 검색에서 “아디다스 컨트리”를 검색했을 때 “자라 옷”, “인스타 릴스에서 본 옷”처럼 넓은 패션 범주의 결과가 함께 반환되는 문제가 있었다.

이는 임베딩 모델이 짧은 상품명이나 브랜드명을 정확히 구분하기보다, 패션 또는 상품이라는 넓은 의미 범주에서 유사하다고 판단했기 때문으로 보인다.

## 8. 품질 관리

테스트 결과를 바탕으로 다음과 같은 품질 관리 방안을 적용하였다.

| 품질 이슈 | 보완 방법 |
|---|---|
| OCR 오인식 | OCR 결과 수정 기능 제공 |
| 빈 본문 저장 | 저장 방지 및 경고 메시지 표시 |
| 빈 검색어 입력 | 검색어 입력 안내 메시지 표시 |
| 검색 결과 없음 | 결과 없음 안내 메시지 표시 |
| 유사도 검색 부정확 | threshold 조정 및 하이브리드 검색 적용 |
| 모델 반복 로딩 | Streamlit cache 사용 |
| 개인정보 가능성 | 이미지 원본 미저장, 로컬 DB 저장 |

품질 관리 단계에서 가장 중요한 점은 기능이 단순히 동작하는 것과 실제 사용자가 신뢰할 수 있는 것이 다르다는 점이었다. 특히 OCR과 유사도 검색은 입력 데이터에 따라 결과가 달라지므로 반드시 테스트와 품질 검토가 필요했다.

## 9. 바이브코딩의 효과

이번 프로젝트에서 바이브코딩은 다음과 같은 효과가 있었다.

OCR 오인식, 유사도 검색 품질 문제, 검색 방식 개선 등에서 해결 방향을 빠르게 도출할 수 있었다.

## 10. 바이브코딩의 한계

바이브코딩의 한계도 확인하였다.

### 10.1 코드 품질 검증 필요

AI가 생성한 코드는 빠르게 동작할 수 있지만, 항상 충분한 예외 처리와 최적의 구조를 갖추는 것은 아니다.

### 10.2 요구사항 범위 조정 필요

AI는 다양한 기능을 제안할 수 있지만, 과제 기간과 목적에 맞는 기능만 선택하는 판단은 개발자가 해야 했다.

### 10.3 실제 데이터 기반 테스트 필요

OCR과 유사도 검색은 구현 자체보다 실제 데이터에서의 품질 확인이 더 중요했다.

### 10.4 개발자의 이해 필요

AI가 작성한 코드를 이해하지 않고 그대로 사용하면 오류가 발생했을 때 수정이 어렵다. 따라서 개발자는 코드의 역할과 흐름을 이해해야 한다.

---

## 11. 프로세스 적용의 교훈

본 프로젝트의 가장 큰 교훈은 다음과 같다.

> 바이브코딩은 개발 속도를 높여주지만, 좋은 소프트웨어를 만들기 위해서는 요구사항 분석, 설계, 테스트, 품질 관리가 반드시 함께 필요하다.

구체적인 교훈은 다음과 같다.

1. 요구사항 분석을 통해 구현 범위를 명확히 줄여야 한다.
2. 설계 없이 바로 코딩하면 기능이 늘어날수록 구조가 복잡해진다.
3. AI가 생성한 코드는 프로젝트 구조에 맞게 검토해야 한다.
4. 기능이 동작하더라도 실제 품질은 테스트를 통해 확인해야 한다.
5. OCR과 유사도 검색처럼 불확실성이 있는 기능은 사용자 수정과 예외 처리가 필요하다.
6. 품질 문제를 발견하고 개선한 기록은 소프트웨어공학 프로세스의 중요한 증빙이 된다.
7. GitHub 커밋과 날짜별 토의 기록은 지속적인 개발 과정을 보여주는 데 효과적이다.

## 13. 결론

CapBox 프로젝트는 바이브코딩을 활용하여 짧은 기간 안에 OCR 기반 스크린샷 아카이빙 웹앱을 구현한 사례이다.

바이브코딩은 코드 초안 작성, 아이디어 구체화, 문서화에서 효과적이었다. 그러나 구현 결과의 품질을 자동으로 보장하지는 않았다. 실제 테스트 과정에서 OCR 오인식, 유사도 검색 부정확성, 예외 처리 필요성을 확인하였다.

따라서 바이브코딩은 단독으로 사용되기보다 요구사항 분석, 설계, 테스트, 품질 관리와 결합될 때 더 효과적으로 활용될 수 있다. 본 프로젝트를 통해 바이브코딩이 소프트웨어공학 프로세스 안에서 활용될 때 개발 속도와 산출물의 완성도를 함께 높일 수 있음을 확인하였다.

# 2026-06-02 토의 기록: 프로세스 적용 교훈 정리

## 1. 오늘의 목표

오늘은 CapBox 프로젝트의 요구사항 분석, 설계, 구현, 테스트, 품질 관리 과정을 돌아보고, 프로세스 적용의 교훈을 정리한다.

이번 과제의 핵심은 단순히 바이브코딩으로 소프트웨어를 만드는 것이 아니라, 요구사항 분석에서 품질 관리까지의 개발 프로세스를 적용하고 그 효과를 논술하는 것이다.

## 2. 지금까지의 진행 요약

현재까지 진행한 내용은 다음과 같다.

1. 주제 선정
2. MVP 범위 확정
3. 요구사항 분석
4. 시스템 설계
5. Streamlit 기본 화면 구현

9. 유사도 검색 구현
10. 하이브리드 검색 개선
11. 테스트 계획 작성
12. 테스트 수행
13. 품질 관리 문서 작성

## 3. 주요 교훈

이번 프로젝트를 통해 가장 크게 느낀 점은 바이브코딩이 개발 속도를 높여주지만, 개발 프로세스를 대체하지는 못한다는 점이다.

AI는 코드 초안을 빠르게 만들 수 있지만, 어떤 기능을 만들지 정하고, 어떤 기능을 제외할지 판단하고, 구현 결과가 실제 요구사항을 만족하는지 확인하는 일은 개발자의 역할이었다.

## 4. 요구사항 분석에서 얻은 교훈

초기에는 모바일 앱 공유 기능까지 포함한 서비스를 생각했지만, 구현 범위가 너무 커질 수 있다는 점을 확인하였다.

따라서 웹 업로드 기반 MVP로 범위를 줄였고, 이 결정 덕분에 과제 기간 안에 핵심 기능을 완성할 수 있었다.

## 5. 설계에서 얻은 교훈

기능별 모듈을 분리한 것이 이후 구현과 개선에 도움이 되었다.

OCR은 `ocr_utils.py`, DB는 `db.py`, 검색은 `search_utils.py`로 나누었기 때문에 특정 기능을 수정할 때 전체 코드를 건드리지 않아도 되었다.

## 6. 구현에서 얻은 교훈

바이브코딩은 구현 속도를 빠르게 해주었다.  
하지만 AI가 만든 코드를 그대로 붙이는 것만으로는 충분하지 않았다.

프로젝트 구조에 맞게 import, 함수 이름, 예외 처리를 조정해야 했고, 실제 실행 후 오류나 부족한 점을 수정해야 했다.

## 7. 테스트에서 얻은 교훈

OCR과 유사도 검색은 실제 데이터를 넣어보기 전까지 품질을 알기 어려웠다.

테스트를 통해 OCR 오인식과 유사도 검색의 부정확한 결과를 확인했고, 이를 품질 관리 단계에서 개선 방향으로 정리하였다.

## 8. 품질 관리에서 얻은 교훈

기능이 동작한다고 해서 품질이 충분한 것은 아니었다.

빈 입력 처리, OCR 실패 안내, 검색 결과 없음 처리, 유사도 threshold 조정, 하이브리드 검색 적용 등은 실제 사용성을 높이기 위한 품질 관리 작업이었다.

## 9. 오늘의 결론

바이브코딩은 빠르게 개발을 시작하고 기능을 구현하는 데 효과적이었다.

그러나 좋은 소프트웨어로 완성하기 위해서는 요구사항 분석, 설계, 테스트, 품질 관리가 반드시 필요했다.

이번 프로젝트는 바이브코딩과 소프트웨어공학 프로세스를 함께 적용했을 때 더 안정적이고 설명 가능한 산출물을 만들 수 있음을 보여준다.

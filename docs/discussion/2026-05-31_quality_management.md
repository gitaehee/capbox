# 2026-05-31 토의 기록: 품질 관리

## 1. 오늘의 목표

5월 30일에 수행한 테스트 결과를 바탕으로 CapBox의 품질 이슈를 정리하고, 이를 보완하기 위한 품질 관리 방안을 문서화한다.

오늘은 새로운 기능을 추가하기보다, 현재 구현된 기능이 사용성, 신뢰성, 데이터 품질, 검색 품질 측면에서 충분한지 점검하는 것을 목표로 한다.

## 2. 테스트 결과에서 확인한 품질 이슈

테스트 결과 다음과 같은 품질 이슈가 확인되었다.

1. OCR이 일부 한글 단어를 잘못 인식하였다.
2. 키워드 검색은 정확한 단어가 포함되어야만 결과를 찾을 수 있었다.
3. 유사도 검색은 짧은 상품명이나 브랜드명 검색에서 부정확한 결과를 반환할 수 있었다.
4. 유사도 검색과 OCR 기능은 모델 로딩 시간이 발생하였다.
5. 저장된 항목의 수정 및 삭제 기능은 아직 제공하지 않는다.

## 3. 품질 관리 방안

확인된 문제를 바탕으로 다음과 같은 품질 관리 방안을 정리하였다.

1. OCR 결과를 저장 전 사용자가 직접 수정할 수 있도록 유지한다.
2. 저장 본문이 비어 있을 경우 저장되지 않도록 처리한다.
3. 검색어가 비어 있을 경우 검색을 수행하지 않고 안내 메시지를 표시한다.
4. 검색 결과가 없는 경우 사용자에게 결과 없음 메시지를 제공한다.
5. 키워드 검색과 유사도 검색을 함께 제공한다.
6. 하이브리드 검색을 통해 검색 품질을 보완한다.
7. 유사도 검색 threshold를 조정하여 관련성이 낮은 결과를 줄인다.

## 4. 프로세스 관점의 의미

이번 품질 관리 단계는 바이브코딩으로 생성한 기능을 검증하고 개선하는 과정이었다.

AI를 활용하면 기능 구현은 빠르게 진행할 수 있지만, 실제 사용자가 기대하는 품질을 만족하는지는 별도의 검토가 필요하다.

특히 OCR과 유사도 검색처럼 입력 데이터에 따라 결과가 달라지는 기능은, 구현보다 테스트와 품질 관리가 더 중요할 수 있음을 확인하였다.

## 5. 오늘의 결론

CapBox는 MVP 수준에서 주요 기능이 동작하지만, OCR 정확도와 검색 품질에는 한계가 있었다.

따라서 사용자가 OCR 결과를 수정할 수 있도록 하고, 키워드 검색과 유사도 검색을 함께 제공하며, 하이브리드 검색을 적용하는 방식으로 품질을 보완하였다.

이번 과정을 통해 바이브코딩은 개발 속도를 높이는 데 효과적이지만, 품질 확보를 위해서는 요구사항 분석, 테스트, 품질 관리 단계가 반드시 필요하다는 교훈을 얻었다.

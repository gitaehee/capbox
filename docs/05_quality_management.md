# 05. 품질 관리

## 1. 품질 관리 개요

본 문서는 CapBox 개발 과정에서 확인한 품질 이슈와 이를 개선하기 위한 관리 방안을 정리한 문서이다.

CapBox는 바이브코딩을 활용하여 구현한 스크린샷 텍스트 아카이빙 서비스이다. 바이브코딩을 통해 이미지 업로드, OCR, 저장, 검색 기능을 빠르게 구현할 수 있었지만, 실제 테스트 과정에서 OCR 정확도, 검색 품질, 예외 처리, 사용성 측면의 품질 점검이 필요하다는 점을 확인하였다.

따라서 본 단계에서는 단순히 기능 구현 여부가 아니라, 사용자가 안정적으로 서비스를 사용할 수 있는지와 구현 결과가 요구사항을 충분히 만족하는지를 중심으로 품질을 점검하였다.

---

## 2. 품질 관리 대상

이번 프로젝트에서 품질 관리 대상으로 삼은 항목은 다음과 같다.

| 품질 항목 | 관리 대상 |
|---|---|
| 사용성 | 사용자가 쉽게 업로드, 수정, 저장, 검색할 수 있는가 |
| 신뢰성 | 빈 입력, OCR 실패, 검색 결과 없음 상황에서 적절히 처리되는가 |
| 데이터 품질 | OCR 결과가 잘못되었을 때 사용자가 수정할 수 있는가 |
| 검색 품질 | 키워드 검색과 유사도 검색이 적절한 결과를 반환하는가 |
| 유지보수성 | 기능별 코드가 모듈로 분리되어 있는가 |
| 보안성 | 개인정보가 포함될 수 있는 스크린샷을 어떻게 다루는가 |
| 확장성 | 향후 모바일 공유, 태그, 삭제/수정 기능을 추가할 수 있는가 |

---

## 3. 테스트 결과 기반 품질 이슈

5월 30일 테스트 수행 결과, 다음과 같은 품질 이슈를 확인하였다.

### 3.1 OCR 정확도 문제

OCR 테스트 결과, 일부 한글 단어가 잘못 인식되는 문제가 있었다.

| 원본 | OCR 결과 |
|---|---|
| 젤 | 절 |
| 살몬 | 살문 |
| 댓글 | 대글 |

이는 OCR 라이브러리의 한계와 이미지 품질, 글자 크기, 폰트, 배경색 등의 영향으로 발생한 문제로 볼 수 있다.

해당 문제는 OCR 기능 자체를 완전히 개선하기보다는, 사용자가 OCR 결과를 직접 확인하고 수정할 수 있도록 하는 방식으로 보완하였다.

---

### 3.2 키워드 검색의 한계

키워드 검색은 사용자가 입력한 단어가 저장된 제목 또는 본문에 정확히 포함되어 있을 때는 안정적으로 동작하였다.

하지만 다음과 같은 한계가 있었다.

1. 정확한 단어를 기억해야 검색할 수 있다.
2. 표현이 조금만 달라져도 검색 결과가 나오지 않을 수 있다.
3. OCR이 단어를 잘못 인식하면 해당 단어로 검색되지 않을 수 있다.

예를 들어 원본에는 “젤”이라는 단어가 있었지만 OCR 결과가 “절”로 저장되면, 사용자가 “젤”로 검색했을 때 결과를 찾지 못할 수 있다.

---

### 3.3 유사도 검색의 한계

유사도 검색은 사용자가 정확한 문장을 기억하지 못할 때 유용하지만, 짧은 상품명이나 브랜드명 검색에서는 부정확한 결과가 나올 수 있었다.

예를 들어 “아디다스 컨트리”를 검색했을 때, “자라 옷”, “인스타 릴스에서 본 옷”과 같은 결과가 함께 반환되는 문제가 있었다.

이는 임베딩 모델이 특정 브랜드명이나 상품명을 정확히 구분하기보다, 패션 또는 상품이라는 넓은 의미 범주에서 유사하다고 판단했기 때문으로 보인다.

따라서 유사도 검색은 키워드 검색보다 항상 우수한 방식이 아니며, 검색 목적에 따라 적절히 보완해야 한다는 점을 확인하였다.

---

### 3.4 모델 로딩 시간 문제

유사도 검색과 OCR 기능은 모델을 사용하는 기능이기 때문에 처음 실행 시 로딩 시간이 발생한다.

특히 EasyOCR과 sentence-transformers 모델은 처음 사용할 때 시간이 걸릴 수 있었다.  
이를 완화하기 위해 Streamlit의 cache 기능을 사용하여 모델을 반복적으로 로드하지 않도록 처리하였다.

---

### 3.5 기능 미구현 항목

현재 MVP에서는 다음 기능이 아직 구현되지 않았다.

1. 저장된 항목 수정
2. 저장된 항목 삭제
3. 이미지 원본 저장 및 미리보기
4. 사용자 계정 및 로그인
5. 모바일 앱 공유 기능

이 기능들은 실제 서비스에서는 필요할 수 있지만, 과제용 MVP에서는 핵심 기능인 OCR, 저장, 검색 흐름에 집중하기 위해 제외하였다.

## 4. 적용한 품질 관리 방법

### 4.1 OCR 결과 수정 기능 제공

OCR 결과가 항상 정확하지 않다는 점을 고려하여, 추출된 텍스트를 사용자가 저장 전에 직접 수정할 수 있도록 하였다.

이를 통해 OCR 오인식이 발생하더라도 사용자가 직접 데이터 품질을 보정한 뒤 저장할 수 있다.

---

### 4.2 빈 입력 예외 처리

사용자가 빈 텍스트를 저장하거나 빈 검색어로 검색하는 경우를 방지하였다.

| 상황 | 처리 방식 |
|---|---|
| 저장 본문이 비어 있음 | 저장하지 않고 경고 메시지 표시 |
| 검색어가 비어 있음 | 검색어 입력 안내 |
| 저장된 데이터가 없음 | 저장 목록 없음 안내 |
| 검색 결과가 없음 | 관련 결과 없음 안내 |
| OCR 결과가 비어 있음 | 직접 입력 또는 다른 이미지 사용 안내 |

---

### 4.3 제목 자동 생성

사용자가 제목을 입력하지 않고 저장할 경우, 본문 앞부분을 자동으로 제목으로 사용하도록 처리하였다.

이를 통해 사용자가 제목 입력을 생략하더라도 저장된 목록에서 항목을 구분할 수 있도록 하였다.

---

### 4.4 하이브리드 검색 적용

유사도 검색의 부정확성을 줄이기 위해 키워드 검색과 유사도 검색을 함께 사용하는 하이브리드 검색 방식을 적용하였다.

하이브리드 검색 방식은 다음과 같다.

1. 먼저 키워드 검색을 수행한다.
2. 키워드 검색 결과가 있으면 해당 결과를 우선 반환한다.
3. 키워드 검색 결과가 없으면 유사도 검색을 수행한다.

이를 통해 브랜드명이나 상품명처럼 정확한 단어 일치가 중요한 검색에서는 키워드 검색이 우선 적용되고, 사용자가 정확한 표현을 기억하지 못하는 경우에는 유사도 검색이 보조적으로 동작하도록 하였다.

---

### 4.5 유사도 threshold 조정

유사도 검색에서 관련성이 낮은 결과가 과도하게 반환되는 문제를 줄이기 위해 threshold 값을 조정하였다.

처음에는 낮은 기준값으로 인해 관련성이 낮은 결과도 검색 결과에 포함되었으나, 기준값을 높여 검색 결과의 품질을 개선하였다.

---

### 4.6 모듈 분리

기능별 코드를 분리하여 유지보수성을 높였다.

| 파일 | 역할 |
|---|---|
| app.py | Streamlit 화면 및 사용자 흐름 제어 |
| ocr_utils.py | OCR 텍스트 추출 |
| db.py | SQLite 저장 및 조회 |
| search_utils.py | 키워드 검색, 유사도 검색, 하이브리드 검색 |

이 구조를 통해 특정 기능을 수정할 때 전체 코드를 수정하지 않아도 되도록 하였다.

---

### 4.7 로컬 저장 방식 적용

스크린샷에는 개인정보가 포함될 수 있으므로, 이번 MVP에서는 클라우드 저장 대신 SQLite 기반 로컬 저장 방식을 사용하였다.

또한 이미지 원본은 저장하지 않고 OCR로 추출한 텍스트만 저장하여 개인정보 저장 범위를 줄였다.

## 6. 남은 품질 개선 과제

현재 MVP 수준에서는 핵심 기능이 동작하지만, 실제 서비스로 확장하려면 다음 개선이 필요하다.

1. 저장된 항목 수정 기능
2. 저장된 항목 삭제 기능
3. 이미지 원본 미리보기 기능
4. OCR 정확도 향상을 위한 전처리
5. 검색 결과 하이라이트
6. 태그 또는 카테고리 분류
7. 검색 성능 최적화
8. 사용자 데이터 보호 정책 수립

---

## 7. 바이브코딩 관점에서의 품질 관리 교훈

바이브코딩은 기능 구현 속도를 빠르게 높여주었다.  
예를 들어 OCR, DB 저장, 검색 기능의 코드 초안을 빠르게 작성할 수 있었고, 구현 과정에서 막히는 부분을 AI와 논의하여 빠르게 해결할 수 있었다.

하지만 테스트 결과, AI가 생성한 코드가 곧바로 충분한 품질을 보장하는 것은 아니라는 점도 확인하였다.

특히 다음과 같은 부분은 개발자의 검토가 필요했다.

1. OCR 결과가 실제로 정확한지 확인
2. 유사도 검색 결과가 사용자의 기대와 맞는지 확인
3. 예외 상황에서 앱이 적절히 반응하는지 확인
4. 불필요하게 넓은 검색 결과를 줄이기 위한 threshold 조정
5. 키워드 검색과 유사도 검색을 조합하는 전략 결정

따라서 바이브코딩을 효과적으로 사용하려면, AI가 만든 결과를 그대로 수용하는 것이 아니라 요구사항, 테스트 결과, 품질 기준에 따라 검토하고 개선하는 과정이 반드시 필요하다.

---

## 8. 결론

이번 품질 관리 단계에서는 CapBox의 주요 기능이 단순히 동작하는지뿐만 아니라, 실제 사용 상황에서 신뢰할 수 있는지 점검하였다.

OCR과 유사도 검색은 입력 데이터에 따라 품질이 달라지는 기능이므로, 사용자의 수정 기능과 하이브리드 검색 방식으로 보완하였다.

이를 통해 바이브코딩 기반 개발에서도 테스트와 품질 관리는 필수이며, 소프트웨어공학 프로세스를 함께 적용해야 결과물의 완성도를 높일 수 있음을 확인하였다.
